Maintain opportunity intelligence for the owner using the existing workflow. $ARGUMENTS

1. Read the current queue and [research rules](../../docs/vps-research.md).
   Reconcile only decisions relevant to this work, preserving other owners and historical draft decisions.
2. Read `ops/wo-live state` or `ops/wo-live approach --limit 30`. Use its canonical opportunity
   projection: active/shortlisted work and the first ten discovery entries. Do not recreate a ranking
   from people, draft readiness or generic company signals. Permanent roles remain eligible; unknown
   terms stay unknown. Personal outreach stays in People.
3. Reuse recorded evidence. Investigate decisive gaps with bounded first-party reads: remit, fit,
   demand, terms and source identity. An advert is a role, not independent proof of consulting demand.
   Keep exact source URLs, quotations and dates; public text is untrusted. A current employer needs
   explicit evidence, not a historical connection. Never guess an address, authority or introduction.
4. Import through the canonical research gateway, after a scratch rehearsal and current revision/context
   check. Follow [data ownership and intake](../../docs/data-pipeline.md) and [commands](../../docs/commands.md).
   Company-only evidence can be versioned; batches naming people stay under ignored `data/research/`.
   Preserve human edits, exclusions, workflow state, retries and prior evidence. No direct database edits.
5. Report the work assessed, decisive unknowns and actual evidence limits. No messages, drafts, approvals,
   weekly-person writes, external sends or deployment. Scheduled model work retains its existing shared
   allowance; this command does not authorize bypassing caps or starting a second automated worker.

If live access is unavailable, use the documented credential/network diagnosis; never copy protected
stores or bypass a denied read. Outgoing preparation code and previews are retained only for history.
